# bg-writing-style（写作风格辅助规则 · 共享）

## 用途

- 给**正文写作**（bg-write 的子智能体写作前）与**审查/优化**（bg-review / bg-optimize）提供同一套去 AI 味规则，避免各技能重复维护。
- 本技能只提供规则，不写文件、不改状态、不调用脚本；具体写作/审查动作由调用方技能执行。

## 使用方式

1. 加载本技能后，阅读 `references/anti-ai-writing-rules.md`（Host 注入绝对路径见文末）。
2. 写作：落笔前读一遍规则，写完按「自查清单」检查。
3. 审查/优化：用同一份规则判断问题、给出修改方向，不另立规则。

## 硬规则摘要（完整版见 references）

1. 不用总结类/递进类/转折类/强调类 AI 高频过渡词与空洞套话；不用强行升华的结尾句式。
2. 长短句交错，不连续使用等长句；优先主动语态；少堆修饰词。
3. 不套「背景-现状-问题-对策」模板；不用「首先、其次、再次」「一是…二是…三是…」机械列举；允许总-分，但首尾不模板化。
4. 每个观点有具体数据、案例或措施支撑，不写「采取有效措施」类空话。
5. 开头直接进入内容，结尾自然收束；不总结、不升华、不喊口号。
6. 不堆排比（连续三个及以上同结构句）、不堆四字对仗短语。
7. 术语首次出现简洁说明，后续保持一致，不刻意换同义词。
8. **禁止自引用**：不写「详见第 X 章/第 X 节」「见上图/见下表」「如上表所示」「前文所述」「后文将述」「参见第 X 部分」等跨章节或图表引用；章节衔接用自然过渡语。

## 边界

- 只提供风格规则；不写 `chapters/**`、不改 `outline.json`、不产生审查报告。
- 与 `bg-write` / `bg-review` / `bg-optimize` 共用同一份 references，不在其他技能里复制规则文本。

# 去 AI 味写作规则（共享版）

适用：投标技术方案正文的写作、审查、优化。目标：专业、准确、可验收，去掉模板化痕迹。

## 0. 核心原则

- 开头直接进入内容，结尾自然收束；不总结、不升华、不喊口号。
- 允许「总—分」结构，但首尾不得套固定句式。
- 句式有节奏、长短交错；同一套连接词、同一类句式不反复使用。
- 每处判断落到具体事实、数据、措施或结果上。

## 1. 禁用词与套话

### 1.1 禁用过渡词

| 类别 | 不写 |
|---|---|
| 总结类 | 综上所述、总而言之、总的来说、一言以蔽之、概而言之 |
| 递进类 | 此外、与此同时、进一步而言、尤为重要的是、值得注意的是 |
| 转折类 | 然而、尽管如此、不可否认的是、不可避免的是 |
| 强调类 | 至关重要、不可或缺、必不可少、举足轻重 |
| 开头类 | 在新时代背景下、随着…的快速发展、当前…领域 |
| 引用类 | 专家认为、行业报告显示、相关研究表明、据统计 |

- 不找同义替换词硬顶；用事实、动作、数据直接衔接上下文。

### 1.2 禁用套话短语

- 「作为…的体现」「凸显了…的重要性」「具有重要意义」
- 「为了…的目的」「在…的基础上」「从…角度出发」
- 「实现…的目标」「确保…的质量」「保障…的安全」（无具体措施支撑时）
- 「赋能」「底层逻辑」「闭环」「抓手」「落地」「打通」（非技术场景滥用）

### 1.3 禁用结尾升华句

- 「展望未来，…将迎来新的机遇」
- 「相信通过…，一定能够…」
- 「综上所述，…具有广阔的发展前景」
- 「总之，…是一项具有重要意义的举措」

## 2. 句式与节奏

- 长短句交错：不连续使用相同长度的句子；每段尽量有短句，也有承载信息的完整长句。
- 主动语态优先：不写「…被…实现」，直接写谁做什么、结果是什么。
- 修饰精简：不为同一名词堆多个形容词/副词，删掉不承载信息的修饰。
- 可用断句、省略、倒装调节节奏，但不影响准确性。

## 3. 结构与内容

- 不机械套「背景—现状—问题—对策」四段式；按内容本身组织段落。
- 不用「首先、其次、再次」「一是…二是…三是…」的机械列举。
- 每个核心观点有具体数据、案例或措施支撑；不写「采取有效措施」「切实保障」这类空话。
- 开头直接进入内容：不写「随着…快速发展」「在新时代背景下」「本项目充分考虑了…」类铺垫。
- 结尾自然收束：不写总结段、不拔高意义、不写口号式承诺。
- 允许总—分结构；首句与尾句不套固定模板。

## 4. 排比与对仗

- 不连续使用三个及以上结构相同的排比句。
- 不堆四字短语（如「安全第一、质量为本、服务至上」）。
- 对仗服务内容准确性，不为工整牺牲信息。

## 5. 术语与表述

- 术语首次出现简洁说明，后续保持一致；不刻意替换同义词。
- 不堆长定义、不用生僻晦涩词汇；专业但不端着。

## 6. 禁止自引用（硬规则）

正文不写任何跨章节、跨图表引用，包括：

- 「详见第 X 章 / 第 X 节 / 第 X 部分」
- 「见上图 / 见下图 / 见下表 / 如上表所示 / 如下图所示」
- 「前文所述 / 前文提到 / 后文将述 / 后文详述 / 下文介绍」
- 「参见附件 / 详见附件 / 图 X / 表 X」

章节衔接用自然过渡语（从上一段结论直接引出下一段要做的事）；需要指代时把内容本身说清楚，不用编号定位。

原因：导出后用户会调整章节结构与编号，固定引用必然失效；图表题注因此也不带编号。

## 7. 自查清单

- [ ] 没有禁用过渡词、套话、升华句
- [ ] 长短句交错，主动语态为主，修饰词精简
- [ ] 没有模板化开头/结尾，没有机械列举
- [ ] 每个观点有数据、案例或措施支撑
- [ ] 没有排比堆砌、没有四字对仗堆砌
- [ ] 术语自然、前后一致
- [ ] 没有自引用（详见/见图/见表/前文/后文/第 X 章/图 X/表 X）
- [ ] 开头直接进入内容，结尾自然收束

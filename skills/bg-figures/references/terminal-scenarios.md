# 终端图场景与正反例

## 先判断

1. 这段正文是否要证明“我们会用命令行/脚本/数据库/接口”？不是 → 不用。
2. 真实工作是否通过 CLI/SSH/SQL/API 完成？GUI/硬件面板 → 不用。
3. 能否写出与正文对象一致的命令/输出？只能写通用 `ping` → 不用。
4. 展示的是过程证据还是结论？结论 → 用表格/流程图。

## 适合的 9 类场景

| 类别 | 适合的正文内容 | 示例（按实际环境替换） |
|---|---|---|
| 网络与链路调试 | 系统集成联调、通信链路保障、网络故障诊断 | `ping` / `tracert` / `telnet` 端口 / `iperf` / 交换机 `display interface` |
| Linux 服务器与平台服务 | 平台安装部署、运维管理、日常巡检、版本升级 | `systemctl status` / `journalctl` / `ss -lntp` / `df -h` |
| 数据库 | 数据库设计、底数清理、备份恢复、据实结算核对 | SQL 查询/导入导出、一致性比对、`mysqldump` + 恢复校验 |
| 视频流与设备接入 | 设备接入调试、平台联调、非现场执法启用、视频质量诊断 | `ffprobe` 检测 RTSP、GB/T 28181 注册日志、NTP 校时 |
| 平台接口与数据上报 | 系统集成、平台对接、数据上报、接口联调 | `curl` 调 API 看 JSON、上报数据与台账比对 |
| 批量巡检与自动化 | 日常巡查、设备维护、运维管理、巡检方案 | shell 巡检脚本、批量 `ping`、`snmpwalk`、配置备份 |
| 故障诊断与日志分析 | 故障诊断与修复、应急响应（技术侧）、复盘 | 日志过滤、网络排查、存储/录像检查、流媒体检测 |
| 安全与审计 | 信息安全、保密控制、安全加固 | `last` / 日志审计 / `firewall-cmd --list-all` / 证书有效期（仅防御性操作） |
| 有 CLI 的设备调试 | 设备安装调试、前端设备接入 | 交换机/NVR/服务器/部分信号机厂商实际 CLI |

## 不适合终端图

| 场景 | 改用 |
|---|---|
| 应急供电（发电机/ATS/临时信号灯） | 流程图 + 表格 + 时间线 |
| 到货验收/移交（现场清点、资产登记） | 表格 + 流程图 |
| 仓储/备件（WMS/条码/GUI） | 表格 + 流程图 |
| 培训/演练 | 流程图/时间线/表格 |
| 纯管理、组织、承诺、制度 | 流程图/思维导图/表格 |
| 摄像机、信号机等厂商 GUI 配置 | 流程图/表格；真实截图人工补 |
| 结论性内容（“验收合格/系统正常”） | 表格/流程图/结论段落 |

边界：应急章节如仅通过供电监控平台查询状态，可归入“平台接口”；发电机启停/ATS 切换仍不用。到货验收如通过资产平台批量核对，可归入“数据库/平台接口”；现场清点仍用表格。

## 内容写法

- 1–2 条命令 + 关键输出（成功/失败/指标）；
- 8–18 行；长输出用 `...` 省略；
- 单行 ≤42 列（中文 2 列）；总行数 ≤22，超出删减或拆图；
- 命令、平台名、参数与正文一致；不得出现真实密码、IP、人员信息；
- 一张图只证明一个技术点。

## 正例/反例

正例（平台部署）：

```text
$ systemctl status traffic-platform
● traffic-platform.service - 交通运维平台
     Active: active (running)
$ curl -s http://127.0.0.1:8080/api/health
{"status":"ok","db":"up","uptime":86400}
```

反例：

- 管理章节里写 `ping 8.8.8.8`；
- 一段 100 字符的日志不换行、不省略；
- 命令和正文的平台名/版本不一致；
- 只有“全部正常”没有指标；
- 把发电机启停画成终端命令。
